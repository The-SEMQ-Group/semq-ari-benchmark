\begin{abstract}
Two identical requests to the same embedding API can return numerically different vectors, yet the frequency and magnitude of this variation are generally not reported by providers. We introduce the AI Reproducibility Index (ARI), a black-box protocol that converts vector outputs into deterministic codes and measures their agreement across execution conditions. Across five commercial embedding APIs, mean exact-code agreement ranges from 0.169 to 1.000. In controlled retrieval experiments, precision and serving changes alter the codes of 47–100\% of documents while Recall@10 remains statistically indistinguishable from baseline. Under synthetic injected perturbations that preserve Recall@10 at 0.988, 11.5\% of 15-hop retrieval trajectories diverge; under bf16, less than 1\% per-token divergence changes 20.8–35.4\% of complete greedy generations. ARI exposes representation-level variation that endpoint quality metrics can otherwise miss.


\end{abstract}

\section{Introduction}\label{sec1}

Reproducibility in deployed inference depends on execution conditions. Changes in numerical precision, hardware configuration, and batching can alter even greedy model outputs [1, 2], and a nominally fixed stack may vary further when its computation is not batch invariant [1]. This paper excludes sampling randomness and studies variation introduced by numerical execution and serving behavior. In our experiments (\S3.2, \S3.3), such changes range from small floating-point differences to per-component perturbations on the order of $10^{-4}$.

Conventional task metrics may not detect this variation. Retrieval quality, for example, can remain unchanged even when representations and ranked lists differ. Hosted API users also lack the backend visibility needed to attribute observed changes to a particular mechanism. The consequence is most noticeable where a system stores a discretization of an embedding rather than the embedding itself, as with semantic IDs in sequence and recommendation models [3]: the stored symbol either matches or does not, and there is no tolerance in which upstream drift can be absorbed.

ARI serves as a common protocol for measuring representation-level reproducibility in systems that expose vector-valued outputs. It standardizes the perturbation conditions, frozen input set, deterministic probe, and reporting rule needed to compare representation drift without serving-internal access. Prior work documents numerical variation in hosted embeddings [4], studies reproducibility across vector-retrieval configurations [5], and makes LLM inference deterministic by construction [6]. ARI addresses a complementary measurement problem: comparing representation-level drift across deployed systems under common, externally inducible conditions, including hosted APIs whose serving internals are unavailable.

\section{The ARI protocol}\label{sec2}

\textbf{Definitions.} For representation-level measurement, the system being tested is $A:\mathcal{X}\to\mathbb{R}^{d}$, mapping an input to an embedding or per-step logit vector. A baseline run holds the specified user-controlled execution axes fixed, and each comparison condition varies one such axis. On self-hosted systems, this can approximate a single-variable intervention. For hosted APIs, backend state is unobservable, so drift is reported as associated with the experimental condition rather than attributed to a specific backend mechanism.

\textbf{The probe.} A deterministic quantizer $Q$ turns each output vector into a code with two bits per dimension, recording each coordinate's sign and whether its magnitude exceeds half a calibrated scale. Because $Q$ is bit-deterministic, it contributes no disagreement of its own, and it operates independently on each coordinate, so observed drift can be traced to specific dimensions. Appendix~\ref{app:calib} gives the quantizer, the calibration rule, and the response model fitted per architecture.

\textbf{Metrics.} ARI has two metrics. ARI-HER measures how often a model produces exactly the same code across repeated runs, concurrent requests, and different times, with HER being the fraction of inputs whose codes match exactly. Because exact agreement can depend on factors such as vector dimension and the sensitivity of the quantizer, HER is not always directly comparable across models. ARI therefore also reports ARI-$\hat\sigma$, which converts the observed disagreement into a normalized estimate of its magnitude. Appendix~\ref{app:calib} describes this calibration and normalization procedure, and Appendix~\ref{app:panel} reports the normalized results. Some tests necessarily differ across providers because their internal systems are not accessible, and the protocol cannot capture backend changes that are not externally observable.

\textbf{Scope and reporting.} Each condition compares one pair of executions over the 1{,}000 frozen inputs, so bootstrap intervals quantify uncertainty across inputs, not across independent realizations of the serving environment. Three independent \texttt{same} and \texttt{proc} realizations on text-embedding-3-large produced between-realization standard deviations of 0.017 and 0.005, respectively, against a within-run confidence-interval half-width of 0.018; \texttt{conc} and \texttt{time} are unreplicated (Appendix~\ref{app:selfhosted}). We apply the protocol to embeddings (ARI-R) and to per-step logits (ARI-D, teacher-forced on the baseline token sequence so every condition sees identical prefixes); agent outcomes are analyzed separately, without quantization. Reports carry a hash-pinned 1,000-item BEIR slice [7], an environment manifest, a result digest, and an Ed25519 signature (Appendices~\ref{app:calib}--\ref{app:verif}).

\subsection{Recall@10 can remain unchanged under large representation drift}

BEIR SciFact (5{,}183 documents, 300 judged queries), all-MiniLM-L6-v2; reference fp32/CPU/4-thread/batch-32, every other condition changing one thing in a fresh process. Intervals are a paired bootstrap over queries, 10{,}000 resamples; per-condition values are in Appendix~\ref{app:scifact}.

Under bf16 and int8, HER falls to 0 while the Recall@10 intervals include zero; a fresh process, a single thread, and batch sizes of 8 and 128 each leave every code intact (HER $=1.000$), so the probe does not respond indiscriminately to the control conditions. Relative to the CPU fp32 reference, GPU fp32 with TF32 enabled changes 47\% of document codes while \(\Delta R@10=0\).

Turning TF32 off restores 0.9992, and a 2x2 over TF32 $\times$ \texttt{use\_deterministic\_algorithms} isolates it (HER 1.000 off, 0.749 on; the flag has no effect): this is consistent with TF32's reduced mantissa amplifying otherwise smaller numerical differences beyond the probe threshold.

Comparing stored top-10 lists also detects many of these changes: bf16 alters 55\% of lists and int8 alters all of them. Unlike HER, however, this approach requires reference queries and rankings, covers only the stored query distribution, and can register inconsequential tie-order changes. 

\vspace{-7pt}\subsection{Small per-step divergence compounds into outcome divergence}

\textbf{Iterative retrieval (controlled stress test).} A self-avoiding nearest-neighbor walk over NFCorpus (3{,}633 documents) embeds the query at each hop and steps to the nearest unvisited document --- an LLM-free iterative-RAG model. We inject \emph{synthetic} isotropic Gaussian per-hop noise over 15-hop walks (100 seeds $\times$ 30 runs), with $\sigma=10^{-3}$ the largest value still passing the standard check (recall@10 $=0.988\ge0.98$); trajectory divergence then grows monotonically with depth to 11.5\% by hop 15, and at $\sigma=0$ it is 0 at every depth. Actual GPU residuals can be structured rather than isotropic [8], so this establishes possible accumulation, not a prediction of API behavior.

Under TF32 every logit code changes while every generated token stays identical; under bf16 fewer than 1\% of tokens change, but 20.8--35.4\% of complete generations differ. Controls and the saturation caveat on whole-code equality at this vocabulary width are in Appendix~\ref{app:deccontrol}.

Among the decoding statistics tested, the quantizer and top-2 logit margin remained sensitive and reproducible at small perturbations; the margin is cheaper but covers only top-ranked logits (Appendix~\ref{app:adversarial}).

\textbf{Limitations.} Our API estimates are based on a single realization of each execution condition, except for the three \texttt{proc} realizations of Appendix~\ref{app:selfhosted}, and therefore do not estimate long-run provider drift rates. The trajectory experiment uses synthetic isotropic noise rather than measured API residuals, and the decoding experiments compare serving configurations on one machine under greedy decoding, leaving drift-vs-sampling separation above temperature 0 untested. ARI also measures representation change rather than whether that change is operationally harmful. Appendix~\ref{app:limits} lists further limitations, while Appendix~\ref{app:adversarial} reports three preliminary claims narrowed by adversarial testing.

\section{Conclusion}\label{sec5}

Rank-based task metrics do not fully characterize representation-level reproducibility. Under one protocol, five commercial APIs span ARI-HER 0.169 to 1.000; precision changes alter 47–100\% of codes with no distinguishable Recall@10 change; and small local differences compound into trajectory- and generation-level divergence. ARI makes this measurable without access to serving internals by separating exact repeatability from calibrated drift magnitude. It complements rather than replaces task evaluation: representation changes may be harmless, and these API measurements are point-in-time observations, not long-run rates. Reproducibility is a property of the deployed system, not something inferable from model identity or endpoint quality alone.\label{bodyend}

\section{Probe and calibration specifics}\label{app:calib}

\textbf{The quantizer.} $Q$ is a four-level symmetric scalar quantizer (SEMQ QUANT) with one model-specific scale $s$, calibrated once as the 99th percentile of absolute coordinate values pooled over a published reference batch. Each coordinate becomes two semantically defined indicators, $Q_s(x_j)=\bigl(\mathbf 1[x_j\ge0],\,\mathbf 1[|x_j|\ge s/2]\bigr)$ --- sign and magnitude region --- for exactly two bits per dimension; the interior edge falls at $s/2$ because two equal-width magnitude bins partition $[0,s]$. With $P=Q\circ A$, all reported quantities are computed on the codes $P(x)$.

\textbf{Response model.} Let $\rho$ be the coordinate change fraction: the fraction of coordinates whose two-bit code differs. Within the calibrated regime,
\[
\mathbb E[\rho]=\kappa\sqrt{2d/\pi}\,\sigma^{b},
\qquad
\hat{\sigma}=\left(\frac{\rho}{\kappa\sqrt{2d/\pi}}\right)^{\!1/b},
\]
with $b$ and $\kappa$ fitted per model; across 13 architectures the exponents have mean $0.979$ and standard deviation $0.028$, and $\kappa\in[0.37,0.76]$. ARI-$\hat\sigma$ averages $\rho$ over the core conditions and inverts once, equivalently pooling all comparisons; inverting per condition and averaging differs by under $1\%$ and preserves the ordering. $\hat\sigma$ is a per-coordinate scale: it normalizes the probe-response model's dependence on dimension and sensitivity, not the vector-level perturbation, which at fixed $\sigma$ grows as $\sqrt d$. It is not a direct estimate of arbitrary serving noise.

\textbf{Calibration model.} Noise is added to the raw representation before any re-normalization: re-normalizing would fold $\sigma$ back onto the unit sphere and mask the linear regime. $\sigma$ is dimensionless, a per-coordinate standard deviation expressed as a fraction of the mean representation norm over the reference batch; the corresponding vector-level perturbation grows as $\sigma\sqrt d$, so $\hat\sigma$ should be read as a per-coordinate scale rather than a relative $L_2$ magnitude.

\textbf{From bits to coordinates.} Reports currently store $\bar H$, the mean changed-bit count, from which the coordinate change fraction follows only up to the exact bound $\bar H/2d\le\rho\le\bar H/d$: a changed coordinate flips one of its two indicators or both. Rather than assume the low-drift limit $\rho\approx\bar H/d$, we propagate both endpoints, so every $\hat\sigma$ we report is an interval and no comparison rests on the conversion. Serializing $\rho=\tfrac1d\sum_j\mathbf 1[Q(x_j)\neq Q(x_j')]$ directly, and refitting $(b,\kappa)$ against it, removes the interval entirely; that is a v0.2 change to the report schema and the published fingerprints. The reference implementation compares packed bytes (four coordinates each) and the signer registry stores fingerprints in that convention, $4\kappa$; $\hat\sigma$ is invariant to the choice, since the constant rescales $\rho$ and $\kappa$ together.

\textbf{Sensitivity spread.} Measured influence spread is 1.00 for quantile binning versus about 16 for a block-microscaled format like NVFP4, whose shared per-block scale smears one perturbed dimension across its whole block. A diagonal sensitivity Jacobian is what lets drift attribute back to specific dimensions.

\section{Verifiability details}\label{app:verif}

The frozen input set is a 1{,}000-item BEIR slice spanning medical, scientific and financial domains, pinned by content hash. Each report carries per-condition HER, $\bar H$ and bootstrap CI, an environment manifest, and a SHA-256 audit digest over the code matrix in fixed input order. The Ed25519 signature covers a canonical JSON serialization (fixed key order and separators) of a manifest that carries the report's SHA-256 alongside the input digest, so the signature attests to the result and the input set jointly; signing only the input digest would attest to neither HER nor $\bar H$. The signing key is held in AWS KMS and listed in a public signer registry, and the verifier runs on the Python standard library without importing the ARI implementation --- a verification requiring the publisher's software is not independent.

\section{Outcome-layer reproducibility (ARI-E)}\label{app:arie}

ARI-E applies the same discipline --- repeat, control, attribute --- to agent outcomes on \texttt{nvidia/Open-SWE-Traces} [9]: two scaffolds (SWE-agent, OpenHands) crossed with two models over ${\sim}18{,}000$ SWE-bench-style instances, up to three rollouts each, graded by each repository's own test suite. An outcome is the repository's own test verdict, which the agent never saw; a benchmark graded by a judge would measure the judge.

The estimator is an agreement gap, not a corrected success rate. On instances with at least two rollouts per side, let $D_{\text{cross}}$ be the rate at which paired verdicts differ across the two conditions and $D_{\text{self}}$ the rate at which repeated rollouts differ within one; we report $\Delta=D_{\text{cross}}-D_{\text{self}}$.

$\Delta$ is descriptive, not causal. It assumes rollouts within a condition are exchangeable, so that $D_{\text{self}}$ estimates the disagreement a fixed condition generates against itself; it is defined only where both sides have at least two rollouts, since one rollout gives no self-consistency control; and it does not estimate a scaffold's effect on task success. It answers a narrower question: how much of the disagreement between two conditions exceeds what either produces against itself. About 22\% of rows were ungraded and dropped.

\textbf{Self-hosted panel.} Eight open models read 1.000 across \texttt{proc}, \texttt{conc} and \texttt{time}, including with BLAS threads unpinned under multithreaded OpenBLAS, and every one collapses to HER $\le 0.094$ under a bf16 serving change. Across the tested self-hosted models, pinning precision eliminated the measured core-condition drift; this is a statement about the tested models, not deployment advice.

\section{Float-level residuals}\label{app:resid}

Of 30 texts embedded in two separated passes against one drifting provider, 3 differed; where they differed, about 2{,}300 of 3{,}072 dimensions changed at magnitude ${\sim}10^{-4}$. This is consistent with backend-level numerical variation rather than isolated last-bit differences, though without provider telemetry we cannot attribute it to a specific mechanism.

\section{Decoding controls}\label{app:deccontrol}

Controls hold on all three models: fresh process, single thread, and TF32 off each read HER 1.0000 with 48/48 generations identical. The model whose vocabulary fits one probe context behaves like the two that require chunking, so the chunked probe path introduces no artifact.

The TF32 row also shows the cost of strictness read in reverse. Over a ${\sim}100$k-token vocabulary, whole-code equality is stringent enough that HER saturates at zero on differences that leave every emitted token unchanged; at this width $\bar H$ and $\hat\sigma$, not HER alone, carry the comparison between conditions. Per-token divergence under bf16 is 0.48--0.79\%, and the 20.8--35.4\% of complete generations that differ is a 26--45x amplification of it, because a flipped token changes the subsequent prefix and can propagate divergence through later decoding.

\section{Alternative probes and scope of the quantizer}\label{app:adversarial}

\textbf{Against simpler statistics.} At the decoding layer we compared the probe with the obvious alternatives under injected logit noise, over $\sigma\in[10^{-4},1]$. KL and JS are second order in the perturbation and are not instruments in the small-$\sigma$ regime at all: at $\sigma=10^{-4}$, KL reads $-5.1\times10^{-10}$, zero to numerical precision and with the wrong sign, where the probe reads $1.33\times10^{-4}$. Top-$20$ set change is sub-linear and token flip is a threshold detector. Two statistics are linear and bit-exact under regrouping of the arithmetic --- the probe and the top-2 logit margin --- while KL moves $4.6\%$ and JS $363\%$ when the same quantity is computed two algebraically equivalent ways. That is the operative distinction: a published KL value is not a number a third party can recompute and confirm, and a code is. It separates the probe from the float-valued alternatives, but not from the top-2 margin.

Additional ablations show that the quantizer is not the only viable probe. At the decoding layer, an 8-byte top-2 logit margin recovers 86\% of the quantizer's signal while storing roughly 1/2000th as much state, and is equally reproducible. The quantizer remains more sensitive to changes below the top-ranked tokens: under token suppression, it detected substantial drift at ranks 3--10 even when the generated token was unchanged. ARI-D is useful when subtle internal drift matters, while a top-2 margin is a cheaper monitor when only output-relevant changes matter. A frozen product-quantization codebook can also serve as a deterministic probe, and other deterministic discretization schemes are possible. Quantile binning's advantage is therefore not that alternatives cannot work, but that it is cheap to verify: its behavior follows from a simple declared rule and one calibration scalar rather than a learned codebook containing thousands of values. 


\section{Remaining limitations}\label{app:limits}

\texttt{mach} and \texttt{lib} are unmeasured for the self-hosted panel; one provider's \texttt{conc} ran at burst 16 rather than 64 due to rate limits; GPU coverage is two architectures. Drift rates are input-distribution dependent, which is exactly why the input set is frozen and hash-pinned. Reports are attested by the leaderboard operator's own key, so attestation proves integrity and origin without making the operator a neutral party. About 22\% of ARI-E rows were ungraded and dropped; if grading failure tracks task difficulty, the surviving set is easier than the whole.
